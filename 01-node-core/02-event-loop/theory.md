Розглянемо це питання детально — від фундаментальної різниці між `while(true)` і `await` до внутрішньої механіки черг Macro- та Microtasks у Node.js.

---

## 1. Чому `while(true)` блокує потік?

JavaScript виконується в **одному головному потоці (Main Thread)**, у якому є **Call Stack (стек викликів)**.

Коли запускається цикл `while(true)` без умов виходу:

1. Фрейм виконання цього циклу потрапляє в **Call Stack** і **ніколи його не залишає**.
2. Оскільки Call Stack зайнятий обчисленням умов і тіла циклу, Event Loop банально **не може отримати управління**.
3. Жодна інша задача (обробка HTTP-запиту, таймер, читання файлу чи навіть Microtask) не може потрапити в Call Stack, поки він зайнятий.

> **Аналогія:** Call Stack — це вузька каса в магазині. `while(true)` — це покупець, який став біля каси і безкінечно рахує дрібні монети, ніколи не відходячи. Усі інші покупці в черзі просто стоять і чекають.

---

## 2. Чому `await` НЕ блокує потік?

Ключовий момент: **`await` — це синтаксичний цукор над `Promise.then()`, який розбиває функцію на дві частини.**

Коли V8 бачить оператор `await`:

1. **Призупинення:** Виконання `async` функції поставить «на паузу» **тільки цю конкретну функцію**, а не весь потік.
2. **Вихід з Call Stack:** Сама `async` функція повертає Promise і **одразу звільняє Call Stack**.
3. **Очікування та Реєстрація:** Проміс чекає на розв'язання (наприклад, відповідь від бази даних або завершення таймера).
4. **Мікрозадача:** Коли проміс промісу резолвиться, **решта функції** (код після `await`) загортається в мікрозадачу і додається в **Microtask Queue**.
5. **Продовження:** Як тільки Call Stack порожній, Event Loop витягує цю мікрозадачу з черги та повертає її в Call Stack для довиконання.

### Демонстрація в коді:

```javascript
async function example() {
  console.log('1: Перед await (синхронно)');
  
  // Функція зупиняється ТУТ, звільняє Call Stack і повертає проміс
  await Promise.resolve(); 
  
  // Цей код виконається як MICROTASK, коли Call Stack звільниться
  console.log('3: Після await (мікрозадача)');
}

example();

console.log('2: Синхронний код після виклику async функції');

// Вивід:
// 1: Перед await (синхронно)
// 2: Синхронний код після виклику async функції
// 3: Після await (мікрозадача)

```

## 3. Детальна анатомія черг: Macrotask vs Microtask

Event Loop у Node.js обробляє дві основні категорії черг задач:

```
┌─────────────────────────────────────────────────────────┐
│                      CALL STACK                         │
└───────────────────────────┬─────────────────────────────┘
                            │ (Коли Call Stack порожній)
                            ▼
┌─────────────────────────────────────────────────────────┐
│                   MICROTASK QUEUE                       │
│  1. process.nextTick Queue (Найвищий пріоритет у Node) │
│  2. Promises / queueMicrotask Queue                     │
└───────────────────────────┬─────────────────────────────┘
                            │ (Виконується ДО КІНЦЯ перед
                            │  переходом до макрозадач)
                            ▼
┌─────────────────────────────────────────────────────────┐
│                   MACROTASK QUEUES                      │
│  1. Timers Phase (setTimeout, setInterval)              │
│  2. Pending I/O Phase                                   │
│  3. Poll Phase (FS, Network I/O)                        │
│  4. Check Phase (setImmediate)                          │
│  5. Close Callbacks Phase                               │
└─────────────────────────────────────────────────────────┘

```

### Порівняльна таблиця:

| Характеристика | Microtask (Мікрозадача) | Macrotask (Макрозадача) |
| --- | --- | --- |
| **Джерела** | `Promise.then/catch/finally`, `await`, `queueMicrotask`, `process.nextTick` | `setTimeout`, `setInterval`, `setImmediate`, I/O операції (`fs.readFile`), мережеві сокети |
| **Правило обробки** | Виконуються **повністю всі** мікрозадачі до єдиної, перш ніж Event Loop зможе перейти далі. | Виконується **одна/обмежена кількість** задач з фази, після чого Event Loop знову перевіряє Microtask Queue. |
| **Пріоритет** | Вищий (виконуються одразу після звільнення Call Stack). | Нижчий (чекають своєї фази в Event Loop). |

## 4. Практичне порівняння: Блокуючий vs Неблокуючий цикл

Щоб зрозуміти, як реалізувати тривалий цикл **без блокування потоку**, порівняємо два підходи:

### ❌ Блокуючий варіант (Синхронний `while`):

```javascript
import http from 'node:http';

http.createServer((req, res) => {
  if (req.url === '/block') {
    // Жоден інший HTTP-запит не буде оброблений!
    let i = 0;
    while (i < 1e10) { i++; }
    return res.end('Done');
  }
  res.end('OK');
}).listen(3000);

```

### ✅ Неблокуючий варіант (Асинхронний квант часу):

Ми можемо розбити важкий цикл на частини (кванти) за допомогою `setImmediate` або `await`:

```javascript
import http from 'node:http';

// Допоміжна функція для віддачі контролю Event Loop
const yieldToEventLoop = () => new Promise((resolve) => setImmediate(resolve));

http.createServer(async (req, res) => {
  if (req.url === '/non-block') {
    for (let i = 0; i < 1e8; i++) {
      // Кожні 1,000,000 ітерацій даємо Event Loop обробити інші запити
      if (i % 1000000 === 0) {
        await yieldToEventLoop(); // Виходить з Call Stack і ставить продовження в Check phase
      }
    }
    return res.end('Done non-blocking');
  }
  res.end('OK');
}).listen(3000);

```

## Результати експерименту

### Експеримент 1: Маршрут `/block`

1. **Дія:** Відкриваєш `/block` у першій вкладці браузера, і одразу ж відкриваєш `/` (або робиш `curl http://localhost:3000/`) у другій.
2. **Результат:** Друга вкладка **чекає кількох секунд і "зависає"**, поки перша не отримає результат.
3. **Чому так відбувається:** Обчислення `fib(42)` виконало більше $800$ мільйонів рекурсивних викликів. Оскільки воно запустилося в **головному потоці (Main Thread)**, Call Stack був повністю заблокований. Event Loop не міг виконати навіть базовий обробник події `http`-сервера для другого запиту.

### Експеримент 2: Маршрут `/worker`

1. **Дія:** Відкриваєш `/worker` у першій вкладці, і одразу ж відкриваєш `/` у другій.
2. **Результат:** Друга вкладка відповідає **миттєво (`ok`)**, поки перша все ще рахує результат у фоні.
3. **Чому так відбувається:** Головний потік лише створив екземпляр `Worker` і повісив слухач події `worker.once('message')`. Це швидка, ненаблокуюча операція. Важка математика `fib(42)` відбувалася у паралельному потоці зі власним ізольованим V8 контекстом та ізольованим Call Stack.

## Коли що використовувати в Node.js?

| Тип задачі | Приклад | Що використовувати |
| --- | --- | --- |
| **I/O-bound** (Ввід/Вивід) | Запити до Бази Даних, HTTP API, читання файлів | Вбудований асинхронний API (`async/await`, Promises, `libuv`) |
| **CPU-bound** (Обчислення) | Обробка відео/зображень, криптографія, складні алгоритми | **`worker_threads`** або окремий Microservice |
